布谷 / BUGU 品牌形象资产盘点

结论先行：现在并存的不是“一套形象有几种尺寸”，而是 5 个版本、4 套视觉体系、3 种完全不同的鸟形 + 1 套并非布谷的后台 Logo。 App 端“咕咕”是圆身、肚皮有心心、两侧翅膀；官网大咕咕是椭圆身、翘尾、嫩芽、爪子；官网徽标是一只没有身体的圆脸鸟；后台则完整沿用 Soybean-Admin 的蓝紫绶带标。 本页所有图形均按仓库内源文件还原，未改色、未重绘。

先看结论：3 个主要不一致

形状与姿态的差异最大，其次才是颜色；后台不是“配色不一致”，而是整套视觉与布谷无关。

01 · 鸟的姿态是三种物种 App：圆身 + 心形肚皮 + 两只分离的椭圆翅膀 + 头顶两颗呆毛，没有尾巴、没有脚、没有嫩芽。
官网大咕咕：横向椭圆身 + 大椭圆肚皮 + 翘起的双尾羽 + 两只脚 + 头顶薄荷嫩芽，肚皮上没有心心。
官网徽标：只有一张圆脸，没有身体、翅膀、尾巴，靠头顶一根嫩芽完成识别。
02 · 同一只鸟，三套珊瑚色与三套“肚子/嘴” App 肚皮 #FFF3EC、嘴 #FFB020、翅膀 #E0523F；
官网肚皮 #FFF6EE、嘴 #FFC966、尾/翅 #F04E27，脚 #E8926B；
后台主色 #646cff，Logo 渐变 #373ebf → #5058e6，浅蓝 #c2d6ff。三端没有共享一个色值定义。
03 · 小尺寸没有成套资产，通知栏直接复用彩色启动图标 通知栏 setSmallIcon(R.drawable.ic_launcher_foreground)：一个 108dp、多色、内容只占中间约 51dp 的前景矢量。 Android 会把 alpha 蒙版整体染白，心形肚皮、眼睛、嘴、腮红全部消失，只剩一坨白色鸟形 + 两道声波；在 24dp 里鸟只有约 11dp 高。 官网 favicon 也只有一个 64 单位的 SVG，没有 16/32/180/512 的简化版或 PNG 兜底。

⑥ 差异结论

形状、配色、线条、姿态、留白，逐项都不一致

  1. 轮廓：App 鸟是“圆 + 两片翅膀 + 两颗呆毛”，重心在肚子；官网大咕咕是“横椭圆 + 翘尾 + 脚”，重心在身体中段；官网徽标只剩“圆形脸 + 嫩芽”，没有身体。三者放在同一屏（见 ④）不像同一个角色。
  2. 识别锚点：App 靠“肚皮上的珊瑚色心心 + 声波”识别；官网大咕咕靠“翘尾 + 薄荷嫩芽 + 脚”；官网徽标靠“嫩芽”；后台靠蓝紫渐变绶带。没有一个跨端稳定的“记忆点”。
  3. 配色：珊瑚主色三端一致（#FA5E38 / #FA5E38），但派生色各行其是：肚皮 #FFF3EC vs #FFF6EE、嘴 #FFB020 vs #FFC966、翅膀 #E0523F vs #F04E27；“墨色”也存在 #1C1917（图标）与 #1E1B18（官网/App 主题）两套。后台直接脱离珊瑚体系。
  4. 线条与细节：App 图标是纯色块 + 一条 1.8 单位的声波描边；官网大咕咕是纯色块 + 渐变，无描边；官网徽标嫩芽用 4 单位描边（在 64 viewBox 里占比 6.25%），缩到 16px 变 1px；后台是 7 段渐变拼接。三种“粗细语言”，无法共用同一套尺寸规则。
  5. 圆角与容器：App 依赖系统自适应图标蒙版（圆/方/水滴都可能）；官网 favicon 是自带完整圆形、直接铺满画布（无安全边距）；后台 favicon 是透明底上的绶带，没有容器。三端图标“外轮廓”不是同一种几何。
  6. 字体处理：App 用 Plus Jakarta Sans（拉丁/正文）+ Space Grotesk（数字）+ 系统中文字体；官网只用系统字体栈，字标是“布谷”800 字重 + 0.02em 字距，配 11px/0.22em 的 BUGU；后台沿用 Soybean 默认字体与标题样式。没有统一的字标文件，也没有中文品牌字体。
  7. 资产库与文档脱节：brand/ 只有 2 份 Markdown。品牌信息体系 §4.5 定的方向是“咕咕侧影（圆身短喙翘尾）+「布谷」圆体字标、最小 24dp”，但现有 5 版没有一个满足（App 无尾、官网徽标无身、大咕咕有尾但无字标，也没有任何侧影版）；§5 把“咕咕四情绪 SVG 导出”列为 v1.1 待办，目录里仍无 SVG/AI/PNG。官网徽标还在 4 处内联复制。当前 5 个版本是同时并存的现状，不是历史迭代（资源文件只有一次 init 提交）。

⑧ 统一方案选项

三项都是“选基准”，不是“选配色”。无论选哪项，通知栏单色剪影都必须单独补一张（P0）。

OPTION A

以 App 图标 / 咕咕为基准

App 是用户每天看见频率最高的一端，且已有四情绪动效与 15 处调用点落地。把“圆身 + 心肚 + 双翅 + 呆毛”定为唯一造型，官网与后台向它靠。

要改
官网徽标（重绘为 App 鸟形并导出 16/32/180/512 + mono）、官网大咕咕（保留或按同形微调）、后台 Logo + 主色、App 补 24dp 通知剪影 + 真 monochrome 层
工作量
App 0.5–1 人日；官网 1–2 人日；后台 0.5 人日；不需要从零设计
风险
官网“圆脸 + 嫩芽”的轻量识别会丢失；大咕咕的翘尾/脚要移除或保留需拍板
代价最低，一致性收益最快。推荐先按 A 做 P0，再决定是否重绘官网大图。
OPTION B

以官网主视觉为基准

官网大咕咕是完整角色（有尾、有脚、有嫩芽、有情绪），叙事最完整。把椭圆身 + 翘尾 + 嫩芽定为唯一造型，App 图标与 Canvas 吉祥物重画。

要改
App 图标 3 个文件重绘、drawGugu 的 4 情绪全部重画（约 40 行绘制逻辑 + 尺寸回归）、后台换标
工作量
App 3–5 人日（含 8–12 处尺寸截图回归）；官网 0.5 人日（补 favicon/OG）；后台 0.5 人日
风险
端侧动画、眨眼、呼吸、振翅都要重调；回归面最大，且小程序图标里尾/脚会先糊掉
视觉最完整，但改动最深。适合下一轮大版本，不适合止血。
OPTION C

重绘一套新基准

以“布谷钟 + 报时鸟”为母题重新设计主 mark（含字标），再补齐 16/24/180/512、单色、深色与四情绪规范，三端同时切换。

要改
设计 1 套主 mark + 1 套四情绪 + 字标；三端全部替换；App Canvas 重画并回归
工作量
设计 2–4 人日 + 落地 2–4 人日；需设计资源或外部委托
风险
最慢；现有 App 动效资产作废；需要品牌决策人拍板造型方向
一次收敛、长期最干净，但周期最长。只有确定要做品牌升级时才选。
