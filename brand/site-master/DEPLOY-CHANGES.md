## 2. 修好的历史缺陷（这部分比"换新图标"更重要）

这次最实质的产出不是视觉更新，是三个长期存在、但一直没人发现的基础缺陷：

### 2.1 favicon 的多个尺寸从来没成功部署过

上线前实测生产服务器：

| URL | 上线前实际返回 | 应该返回 |
|---|---|---|
| `/favicon-16.png` | `200` + `Content-Type: text/html` + 1060 字节 | `image/png` |
| `/favicon-32.png` | 同上 | `image/png` |
| `/favicon-48.png` | 同上 | `image/png` |
| `/favicon-512.png` | 同上 | `image/png` |
| `/apple-touch-icon.png` | 同上 | `image/png` |

`text/html` + 1060 字节是 nginx 的 SPA 兜底页（`try_files` 找不到文件就返回 `index.html`）。也就是说：`/var/www/bugu-web` 里除了 `favicon.svg`，**这些 PNG 从来没有被部署上去过**。仓库里有文件、构建里也有文件，但服务器目录里没有——所以浏览器一直拿到一张 HTML 当图片，表现就是图标不显示或回退到默认。

上线后同一批 URL 全部返回 `image/png`（实测字节数 572 / 1114 / 1678 / 14599 / 4789）。

### 2.2 OG 标签从来没写过

上线前的 HTML 里只有三条 `rel="icon"`，**没有任何 `og:*` 标签**（连 `og:title` 都没有）。所以过去无论分享到哪个平台，都不会有标题、描述和封面图，只有一条裸链接。

### 2.3 静态资源没有版本参数

`favicon`、`icon` 这类资源被浏览器长期缓存，改文件不改 URL 时用户看到的还是旧图。本次统一加了 `?v=20261110`，让浏览器主动重新取。

> 前两条属于部署链路与页面标记的缺陷，与设计无关。即使这次不换视觉，也应该修。

## 4. 存量用户可能遇到的缓存问题

这些不是故障，是客户端缓存的正常表现，处理方式如下：

| 现象 | 原因 | 处理 |
|---|---|---|
| 老标签页里页头还是旧图形 | 页面本身被缓存，或标签页未重新加载 | 刷新（Cmd/Ctrl+R）；仍不生效则强制刷新（Shift+刷新） |
| 标签页图标还是旧的 | Chrome/Safari 对 favicon 缓存极久，部分版本不认 `?v=` | 关闭该标签页重新打开；或清一次站点数据。新用户不受影响 |
| 微信/飞书分享出去还是旧卡片或无图 | 平台按 URL 缓存抓取结果，通常数小时到数天 | 用带参数的链接重新分享（如 `?v=20261110`）可绕过旧缓存 |
| iOS 主屏图标没变 | 主屏图标在"添加到主屏幕"时固化 | 删除后重新添加 |
| 后台仍显示旧 Logo | 同浏览器缓存 | 强制刷新 |

`?v=20261110` 只能解决"浏览器愿意重新请求"的问题，不能强制已经缓存的分享卡片刷新——那由平台侧决定。

## 5. 明确不包含什么

1. **首页那只大咕咕插画没有改。** 它是这次母版的取材来源（页头图形、favicon、OG 卡的几何与配色都从它和站点现有样式里提取），本身保持原样。
2. **App 图标这次不会变。** 桌面图标、通知栏小图标、Android 13+ 主题单色层四个资源文件已经改好并放在工作区，但**尚未构建、未装机、未验证**，要等下一次 App 构建发布才对用户生效。Play 商店的 512 图标也还没有上传。
3. **没有改任何业务逻辑。** 后端接口、数据库、WebSocket、推送、闹钟逻辑、页面路由、文案内容均未变动；这次只动了静态资源与页面 `<head>` 标记。
4. **没有改后台的功能与布局**，只换了品牌图形与图标。
5. **没有引入新的品牌色。** 所用颜色全部来自官网现有样式表，没有新增色值。
